# 現行規格

本表描述 MVP 設計及目前實作規則，不代表每項都已完成真人驗證。快照：2026-11-18。

| 編號 | 規則 | 驗證界線 |
|---|---|---|
| S1 入口 | 個人文字入口；群組須真正 @Bot，純文字假裝 @ 不算 | 本機路由測試與同一人跨入口真人測試 |
| S2 身分 | 個人以頻道與使用者識別；群組另加聊天室情境；不同入口不自動共用席位 | 不公開原始識別值；不同真人尚待實測 |
| S3 單席位 | 所有入口共用同一 NotebookLM 帳號與一個席位 | 不能宣稱多人同時生成答案 |
| S4 FIFO | 入隊去重，依服務接受的順序分配；輪到後發邀請 | 訊息在不同手機上的發送時間不等於後端收件順序 |
| S5 邀請 | 輪到後須重新提問；等候原問題不保留；邀請無回應會到期 | 未開始對話且歷史為空時可釋放邀請，不必宣稱每次都刪聊天 |
| S6 多輪 | 只有目前持有者與原聊天室情境可續問；單題處理中不另開平行查詢 | 真 LINE 多輪證據來自 Koopman，照護本輪各一題 |
| S7 使用上限 | 第一題被接受起，最長 600 秒；最後一次被接受問題起，閒置 120 秒 | 不是從答案回覆起算；完整真實 600 秒尚待測 |
| S8 結束 | 主動「結束」、到使用上限或閒置，停止當輪並準備交接 | 排程每分鐘檢查，忙碌可能延後 |
| S9 清除 | 僅針對專用測試帳號可識別的當輪聊天；清除且歷史核對為空後才交接 | conversation_id 可沿用；ID 改變不是驗收必要條件 |
| S10 異常 | 有生成中工作先等結果；未知歷史、清除失敗或工作結果不明時暫停 | 不把 HTTP timeout 當作上游停止，不靠固定等待直接換人 |
| S11 回覆 | 答案與通知回到原聊天室；群組答案公開 | API 接受不等於成員已讀；引用失敗不可標為已核對 |
| S12 邊界 | 不修改筆記本來源、分享或 7A2 成果 | 運行環境與文件 Repo 各自獨立 |

## 計時與處理中的問題

到期時若尚有問題在處理，狀態進入 DRAINING，停止接受新題，待已知結果結束後再清除。上游結果不明則 PAUSED。每分鐘 tick 的延遲及執行容量限制須在展示時說明，不承諾秒級回收。

## 引用狀態

Koopman 測試曾成功核對引用。最新照護兩則答案雖含引用數字，但驗證旗標為 false、可核對摘錄為 0。公開說明採「答案已回傳，引用核對未通過」，不得混為整輪全部通過。
