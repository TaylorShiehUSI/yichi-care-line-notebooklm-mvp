# 從想法到方案：決策紀錄

本頁回顧歷程，不把未採用構想寫成已實作。快照：2026-11-18。

| 階段 | 假設／問題 | 發現或取捨 | 結果 |
|---|---|---|---|
| D1 起點 | GAS 能否直接查公開／共享 NotebookLM？ | 程式查詢及檢視者權限是最不確定的一步 | 先用 Python 獨立查一題，與 LINE 分開驗 |
| D2 登入 | 使用者瀏覽器看得到，是否代表程式可問？ | Python 必須有自己的有效登入狀態及筆記本權限 | 專用檢視者帳號；Google Cloud 部署身分另行區分 |
| D3 執行位置 | 本機或 Cloud Run | 本機須開機；雲端便於他人試用，但有額度、費用及登入維護問題 | 採雲端逐步驗證，先單題再服務化 |
| D4 隔離 | Channel ID、使用者 ID 能否分開 NotebookLM 對話？ | 身分路由不會自動建立上游隔離；同帳號會延續上下文 | 當輪保留脈絡，交接前清除 |
| D5 隔離判準 | 清除後應產生新 conversation_id？ | ID 可能沿用 | 核對歷史並以測試標記正反向對照；證據來自 Koopman，非一般性保證 |
| D6 容量 | 用 20 帳號分配 20 人 | 帳號建立、維護與認證增加成本；沒有完成驗證 | 暫緩帳號池，改單帳號單席位 |
| D7 公平 | A 一直追問，B 如何開始？ | 要有等待通知、期限及 FIFO | A 可多輪，最長 10 分鐘／閒置 2 分鐘；B 等候後重新提問 |
| D8 雲端狀態 | GAS 主控全部？ | 原始簽章驗證與持久化原子狀態另設責任 | edge 驗簽、worker／Firestore 管狀態，GAS 判業務動作 |
| D9 群組 | 同群組的人可否共同追問？ | 須避免不同人混入目前使用者上下文 | 只有持有席位的使用者＋聊天室可續問；其他人排隊 |
| D10 真實語料 | 從 Koopman 切至照護 | 發現測試帳號已有 1 則既有聊天，先停止 | 使用者另行明確同意後清除；核對 49 筆來源目錄前後一致 |
| D11 成果邊界 | 資訊流通了是否等於全部成功？ | 照護引用旗標 false；不同真人與長期穩定性未證實 | 接受技術 MVP，保留驗證缺口，功能凍結 |
| D12 文件交付 | 與 7A2 共用 Repo？ | 架構及證據不同，容易混淆版本 | 新建獨立私有文件 Repo，使用者看完再決定公開 |

使用者決定需求與授權；Codex 整理、實作及核對；Claude 參與設計與摘要複核。Claude 的摘要審視不等於獨立重跑測試。既有 7A2 始終為不可修改邊界。
