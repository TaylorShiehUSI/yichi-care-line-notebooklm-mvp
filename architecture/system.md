# 系統架構與責任

快照：2026-11-18。本頁為實際元件角色摘要，省略部署識別資料及憑證；不是一鍵部署指南。

| 元件 | 責任 | 邊界 |
|---|---|---|
| LINE | 個人／群組事件、通知與答案 | 群組答案公開；API 接受不證明已讀 |
| 公開 Cloud Run edge | 驗 LINE 原始訊息簽章、接受合法事件 | 不是 GAS 驗 LINE 標頭 |
| Firestore intake／meta | 持久化收件與順序資料 | 跨入口順序以服務接受為準 |
| Cloud Tasks | 喚醒私有 worker，控制工作派送 | 21 項早期 Firestore 模擬不涵蓋其完整故障重試 |
| 私有 Cloud Run worker | 正規化路由、呼叫 GAS、排隊／單席位、Python 查詢、清除及通知處理 | 受 IAM 保護；未知上游結果不直接交接 |
| GAS | 加入／提問／離開／狀態等業務動作判定 | 與 worker 的橋接請求使用 HMAC；不是全部狀態的唯一保存處 |
| Firestore queue／outbox | 席位、等待、代數、工作與通知狀態；CAS 更新 | 不把 Cloud Run 本機 SQLite 當共享狀態 |
| NotebookLM | 專用檢視帳號查詢指定共享筆記本 | 透過非官方 notebooklm-py；登入與 GCP 部署身分不同 |
| Cloud Scheduler | 每分鐘觸發檢查邀請／閒置／使用上限 | 排程或忙碌可造成回收延後 |

## 驗證與安全責任

LINE 原始簽章驗證、worker／GAS HMAC、私有服務 IAM 是不同責任，不混為同一項。NotebookLM 帳號登入狀態在受控環境供程式使用，GAS 不應取得 Google Cookie；本 Repo 不保存任何這類材料。

## 路由與上下文

對話席位識別包含頻道、使用者與聊天室情境。同一人從個人與群組進來視為不同情境，仍共用一個全域席位。通知保存原收件目標，不能在交接後把舊答案重新指定給下一人。

## 持久化與異常

工作及通知狀態保存在 Firestore。生成中、輸出結果不明、清除失敗或未知歷史等情況必須保守處理；資料持久化不等於已完成所有重啟／故障接管驗證。

目前沒有多帳號池，也不宣稱把多個帳號同時登入雲端即完成隔離。參見[狀態機](state-machine.md)及[驗收矩陣](../acceptance/acceptance.md)。
